# Безопасность Siftly

## Граница доверия

Поддерживаемая платформа — Windows. WebView не считается доверенным источником путей: выбор папок выполняется в Rust нативным диалогом. Backend сохраняет канонические пути, список результатов последнего сканирования и разрешает копирование только уникальных записей из этого списка. Новое сканирование или выбор источника сбрасывает старое разрешение.

Команды доступны только локальному окну `main` через явно объявленные разрешения приложения. JavaScript не получает разрешения на самостоятельный вызов диалогового плагина. Системное подтверждение копирования создаётся в Rust и необходимо даже при прямом вызове IPC.

Release CSP разрешает локальные скрипты и IPC, запрещает сторонние сетевые соединения, фреймы, объекты и отправку форм. Inline-стили разрешены для React и индикаторов прогресса. Dev CSP дополнительно разрешает Vite на localhost:1420, WebSocket HMR и inline-скрипты разработки; она не применяется к релизу.

## Файловые операции

- Имена резервируются атомарно через `create_new`; перезаписи нет.
- Каталоги и их предки удерживаются дескрипторами без совместного удаления, чтобы предотвратить перенаправление путей во время операции.
- Источник проверяется по открытому дескриптору; ссылки и reparse points не копируются.
- `Zone.Identifier` переносится до основного содержимого, не более 64 КиБ. Ошибка чтения/записи метки приводит к отказу копирования и очистке, а не к незаметному снятию защиты.
- Незавершённый файл удаляется через `FileDispositionInfo` на ещё открытом дескрипторе, а не по имени после закрытия. Ошибка очистки сообщается пользователю.
- При аварийном завершении или отключении питания частичный файл всё ещё может остаться; автоматическое восстановление после аварии пока отсутствует.
- ACL, владелец и прочие ADS не сохраняются. Копия получает права из назначения; это не средство полного резервного копирования.

Лимиты и подробный контракт: [копирование](copy-semantics.md).

## Проверка зависимостей

При аудите 26 сентября 2026 года `pnpm audit` не сообщил известных уязвимостей. Через OSV проверены 443 registry-пакета из Cargo.lock. `cargo audit` не был установлен; OSV использовался как отдельная проверка версий, не как анализ достижимости уязвимого кода.

- `glib 0.18.5`: [RUSTSEC-2024-0429](https://rustsec.org/advisories/RUSTSEC-2024-0429.html). Пакет отсутствует в текущем Windows-дереве, проверено `cargo tree --target x86_64-pc-windows-msvc -i glib`. Перед портированием на Linux требуется повторный аудит.
- `proc-macro-error 1.0.4`: [RUSTSEC-2024-0370](https://rustsec.org/advisories/RUSTSEC-2024-0370.html), не поддерживается; отсутствует в текущем Windows-дереве.
- Пять `unic-* 0.9.0`: предупреждения о прекращении поддержки ([описание семейства](https://rustsec.org/advisories/RUSTSEC-2025-0081.html)), приходят через `urlpattern → tauri-utils`. Это оставшийся риск сопровождения, не исправленный обновлением и не подтверждённый эксплойт. Не следует скрывать предупреждения или подменять зависимости несовместимыми версиями; нужно отслеживать обновления Tauri.

## Что ещё проверить вручную

- Desktop-сценарий выбора папок, отказа/согласия в системном подтверждении и копирования в dev/release.
- Перенос файла с меткой на FAT/exFAT: ожидается явная ошибка и отсутствие успешной незащищённой копии.
- Чистая Windows, сетевые папки, антивирусы и нестандартные ACL.

Автотесты покрывают разрешённые/чужие пути, дубликаты выбора, сброс результатов, лимиты, перенос и превышение размера метки, блокировку переименования каталога, отмену и очистку. Это не независимый пентест и не гарантия отсутствия всех уязвимостей. Приложение не следует запускать с правами администратора для обхода ошибок доступа.
