# Выпуск обновлений Siftly

Обновления размещаются в публичном репозитории `nolllerrr/siftly`. Workflow `.github/workflows/release.yml` запускается при отправке тега `vX.Y.Z`, собирает Windows x64 NSIS-установщик и создаёт **черновик** релиза с установщиком, `.sig` и `latest.json`. Сам по себе черновик не предлагается пользователям как обновление.

## Подпись

Приватный ключ хранится вне проекта: `%USERPROFILE%\.siftly-signing\updater.key`. Доступ к локальной папке ограничен текущим пользователем и SYSTEM. Ключ без пароля загружен в GitHub Actions Secret `TAURI_SIGNING_PRIVATE_KEY`; дополнительный Secret пароля не требуется. Workflow получает ключ только в шагах проверки наличия и подписания.

Сохраните резервную копию ключа в защищённом хранилище. Не добавляйте его в Git, артефакты, сообщения или логи. Потеря ключа делает невозможным выпуск обновлений для уже установленных приложений с прежним публичным ключом. Доступ на запись в репозиторий и возможность менять workflow нужно давать только доверенным людям.

В приложении находится только публичный ключ. Rust использует фиксированный HTTPS endpoint и принимает установщик только из Releases этого проекта. Проверяется криптографическая подпись установщика и соответствие подписанной версии манифесту. Это **не Authenticode-подпись Windows** и не устраняет предупреждения SmartScreen.

## Новый релиз

1. Измените версию одновременно в `package.json`, `src-tauri/tauri.conf.json` и `src-tauri/Cargo.toml`; обновите Cargo.lock командой `cargo check --manifest-path src-tauri/Cargo.toml`.
2. Проверьте `pnpm test`, `pnpm build`, `cargo test --manifest-path src-tauri/Cargo.toml --locked`.
3. Закоммитьте и отправьте изменения. Создайте и отправьте соответствующий тег, например для версии 0.1.1:

   ```powershell
   git tag v0.1.1
   git push origin v0.1.1
   ```

4. Дождитесь успешного workflow **Windows release**. Скрипт запрещает несовпадение версий и prerelease-теги. При сбое исправьте причину; не публикуйте неполный черновик.
5. В черновике проверьте установщик, `.sig`, `latest.json`, версию, адрес установщика и список изменений. Установите пакет на тестовой Windows, проверьте запуск, поиск, копирование, отмену.
6. Опубликуйте проверенный черновик как обычный релиз (не prerelease), назначив его Latest. Только после этого `releases/latest/download/latest.json` станет доступен клиентам.

Уже опубликованные теги и подписанные установщики не заменяйте: исправления выпускайте с новой увеличенной версией. Не публикуйте старый релиз как Latest.

## Проверка полного цикла

Потребуются две разные версии. Установите первую с поддержкой обновлений, опубликуйте вторую и проверьте автоматическую/ручную проверку, отказ от установки и повторное согласие, загрузку, проверку подписи, запуск новой версии. Во время копирования установка должна быть недоступна. Отключение сети не должно мешать работе с файлами. Подменённый установщик, подпись или подписанная версия должны приводить к ошибке до запуска установщика.

Этот полный сценарий и workflow на GitHub необходимо проверить после отправки кода и публикации релизов; локальные тесты их не заменяют. Режим `pnpm tauri dev` намеренно не устанавливает обновления. Сборкам без updater требуется однократная ручная установка новой версии.

Локально 27 сентября 2026 проверены 34 Rust-теста, 20 frontend-тестов, clippy и release-сборка 0.1.0. Для собранного NSIS-пакета отдельно проверены подпись публичным ключом из конфигурации, наличие подписанной версии 0.1.0 и отклонение изменённого установщика. Интерактивная установка и полный цикл обновления пока не проверены.

## Локальная сборка

```powershell
$env:TAURI_SIGNING_PRIVATE_KEY = "$env:USERPROFILE\.siftly-signing\updater.key"
try { node node_modules/@tauri-apps/cli/tauri.js build --ci -- --locked }
finally { Remove-Item Env:TAURI_SIGNING_PRIVATE_KEY -ErrorAction SilentlyContinue }
```

Установщик и подпись находятся в `src-tauri/target/release/bundle/nsis/`. `latest.json` для GitHub создаёт workflow, а не обычная локальная сборка.
