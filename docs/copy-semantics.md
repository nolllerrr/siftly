# Контракт копирования Siftly

Поиск и копирование выполняются в Rust. Реализация и автоматические проверки не зависят от внешнего интерпретатора. Ожидаемые результаты закреплены в нативных тестах.

## Данные и имена

- Папки выбираются нативным диалогом и хранятся в Rust. IPC разрешает копирование только уникальных путей из последнего сканирования в выбранную папку. Кнопка **Copy selected** запускает копирование без дополнительного подтверждения. Служебный Windows-префикс скрыт только в интерфейсе; исходные пути используются для IPC и файловых операций.
- Копируется только явно переданный список файлов, последовательно, в одну папку. Одновременно разрешена одна операция или диалог.
- Обход каталогов не выполняется на этапе копирования. Символические ссылки и Windows reparse points пропускаются при сканировании и не копируются. Для облачных файлов может потребоваться предварительно создать обычную локальную копию.
- Существующие файлы и каталоги защищены атомарным `create_new`. При коллизии добавляется `_1`, `_2` и далее перед последним расширением, не более 10 000 попыток на файл. Имена уже зарезервированных копий учитываются без регистра.
- `create_new(true)` резервирует имя атомарно. Если имя занял другой процесс, выбирается следующий суффикс. Существующий объект не открывается на запись.
- Один буфер размером 1 МиБ переиспользуется для всей очереди. Отмена проверяется между блоками, перед началом файла и перед сохранением метаданных.
- На Windows источник открыт с разрешением совместного чтения, без совместной записи и удаления. Уже открытый несовместимым способом файл даёт ошибку; очередь продолжается.
- Размер для копирования берётся из открытого файла, а не из устаревшего результата поиска. После чтения повторно проверяются размер и дата изменения.

## Метаданные

В Windows сохраняются даты создания, изменения и последнего доступа, а также атрибуты `READONLY`, `HIDDEN`, `SYSTEM`, `ARCHIVE`, `NOT_CONTENT_INDEXED`. Даты устанавливаются на открытом файле после завершения записи; атрибуты — последним шагом. Ошибка сохранения этих данных означает ошибку всего файла.

Windows-поток `Zone.Identifier` переносится побайтно до записи основного содержимого. Если существующую метку невозможно прочитать или сохранить (в том числе на файловой системе без ADS), копирование этого файла завершается ошибкой с очисткой незавершённого результата. Размер метки ограничен 64 КиБ. Отсутствие метки допустимо.

Не обещается перенос ACL, владельца, остальных альтернативных потоков NTFS (ADS), режима шифрования, сжатия, разреженности и служебных атрибутов облачного хранилища. Это не полноценный файловый бэкап.

Копии получают исходные даты создания и последнего доступа, а не время выполнения операции. Сохранение этих дат и перечисленных атрибутов проверяется напрямую по метаданным исходного файла. Структура `CopyResult`, содержимое копий и правила переименования также закреплены тестами с фиксированными ожидаемыми значениями.

## Отмена, ошибки и прогресс

Во время копирования `bytes_copied` включает текущий записанный блок. Если файл не завершён, его байты вычитаются из прогресса; итоговый `CopyResult.bytes_copied` учитывает только успешно завершённые файлы. Поэтому после отмены шкала может уменьшиться.

При ошибке или отмене незавершённый файл Windows помечается на удаление через его открытый дескриптор и затем закрывается. Удаления по потенциально подменённому пути нет. Каталоги и их предки удерживаются открытыми без разрешения удаления/переименования на время операции. Если удаление не удалось, точный путь и причина попадают в ошибки. На других ОС безопасная очистка пока не реализована: частичная копия сохраняется с явной ошибкой. Поддерживаемая платформа приложения — Windows.

Успешно завершённые копии сохраняются. Отменённый текущий файл и не начатые файлы учитываются в `skipped`, ошибка отдельного файла — в `failed`.

Удаление незавершённой копии гарантируется только при штатной обработке ошибки/отмены; принудительное завершение процесса и потеря питания могут оставить частичный файл. Удаление таких файлов после перезапуска пока не реализовано.

Прогресс передаётся отдельным Tauri Channel на каждую операцию. Окончательный результат имеет приоритет над запоздавшими событиями. Отмена хранится в памяти приложения без marker-файлов.

## Проверка

Лимиты одной операции: 10 000 результатов/копируемых файлов, 10 000 каталогов, 1 000 000 проверенных файлов, 1 000 ошибок сканирования плюс итоговое предупреждение. При достижении лимита поиск возвращает `truncated: true` и частичные результаты. IPC ограничивает запрос 8 МиБ, список расширений — 100 значениями до 32 байт. Для больших наборов следует сузить поиск.

```powershell
# Поиск, копирование и контракты результатов
cargo test --manifest-path src-tauri\Cargo.toml

# Логика frontend, обработка прогресса и каналов
pnpm test
```

Проверки используют собственные временные файлы. В них входят конкурентные коллизии, отмена внутри и между файлами, заблокированный источник, недоступное назначение, нулевой размер, копирование в исходную папку, ошибки потока ввода/вывода и точность метаданных. Ручной smoke-test Tauri после миграции и проверка установщика на чистой Windows остаются отдельными задачами.

Справочники: [Rust FileTimes](https://doc.rust-lang.org/std/fs/struct.FileTimes.html), [Windows FileTimesExt](https://doc.rust-lang.org/std/os/windows/fs/trait.FileTimesExt.html), [Windows-атрибуты](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-setfileattributesw).
