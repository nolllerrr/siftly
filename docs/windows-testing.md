# Проверка Siftly на Windows

## Что проверено 2 октября 2026

Пользователь сообщил об успешном прохождении ручных проверок версии 0.1.1 в Windows Sandbox: поиск по расширениям и диапазону дат, вложенные папки, копирование выбранных файлов, разрешение конфликтов имён при повторном копировании и отмена большого файла.

Первый запуск не удался: регистрация WebView2 указывала 154.0.4258.48, а найденный runtime находился в папке 154.0.4258.53. Установщик WebView2 завершался ошибкой 11; журнал содержал `Could not create temporary path` и `Access denied (0x5)`. Свободно было около 76 ГБ. Запуск Siftly с процессной переменной `WEBVIEW2_BROWSER_EXECUTABLE_FOLDER`, указывающей на имеющуюся папку runtime, сработал.

Похожая регрессия установки WebView2 в Sandbox зарегистрирована в [MicrosoftEdge/WebView2Feedback #5697](https://github.com/MicrosoftEdge/WebView2Feedback/issues/5697). Совпадение симптомов не доказывает, что все ошибки имеют одну причину.

## Повторная проверка версии 0.1.2

Локально проверены 40 обычных Rust-тестов и отдельный тест нативного загрузчика установленного WebView2, 23 frontend-теста, TypeScript, сборка интерфейса и clippy без предупреждений. Собран NSIS-установщик 0.1.2 с подписью обновления. Подпись проверена публичным ключом из конфигурации; подписанная версия соответствует 0.1.2, изменённые байты установщика проверку не проходят. Это не проверка Authenticode и не проверка интерактивного запуска в Sandbox.

1. Использовать новый `Siftly_0.1.2_x64-setup.exe`.
2. Закрыть старый Siftly. Установить новую версию в Sandbox.
3. Запустить через ярлык или Проводник, без PowerShell с вручную заданным путём WebView2. Если используется прежняя консоль, сначала выполнить `Remove-Item Env:WEBVIEW2_BROWSER_EXECUTABLE_FOLDER -ErrorAction SilentlyContinue`.
4. Проверить запуск и повторное открытие, затем повторить поиск и копирование.

Версия 0.1.2 при ошибке стандартного обнаружения проверяет версии в известных системных папках Microsoft. Выбирается самая новая версия, которую принимает нативный загрузчик WebView2; неполные установки пропускаются. Исправление не устанавливает отсутствующий runtime и не исправляет ошибки установщика Microsoft.

2 октября 2026 после передачи установщика 0.1.2 и инструкции запускать приложение через ярлык или Проводник без ручного обхода пользователь подтвердил, что приложение открывается. Повторное открытие и повторные проверки файловых операций именно на 0.1.2 отдельно не подтверждены.

После инструкции закрыть и заново открыть Windows Sandbox пользователь сообщил, что на чистой Windows всё работает. В контексте этой проверки результат фиксируется как успешная проверка 0.1.2 в новой чистой сессии Sandbox. Проверка в полноценной виртуальной машине и сценарий установки с изначально отсутствующим WebView2 этим не подтверждены.

## Полная проверка установки

Sandbox не заменяет чистую Windows в полноценной виртуальной машине для проверки зависимости WebView2. Использовать чистую Windows 10/11 x64 без инструментов разработки, со снимком состояния перед установкой.

- Установить setup с доступом к сети; проверить запуск без переменных обхода и повторный запуск после перезагрузки.
- Проверить обычную учётную запись, поиск, копирование и отмену.
- Проверить удаление и повторную установку.
- Если WebView2 изначально отсутствует, отдельно проверить его установку setup. Текущий режим Tauri скачивает bootstrapper и требует сети для установки runtime.
- Для проверки обновлений установить предыдущую версию с updater и использовать новый опубликованный подписанный релиз. Проверить загрузку, подтверждение, запуск новой версии и работу приложения при недоступной сети.

Проверка 0.1.1 с обходом подтверждает работу файловых операций; для 0.1.2 пользователь подтвердил запуск после исправления и работу в новой чистой сессии Sandbox. Проверка в полноценной виртуальной машине без WebView2 и полный цикл обновления ещё требуют проверки.
